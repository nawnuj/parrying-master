# 개발 일지

Parrying Master의 기능 구현 과정과 테스트 결과를 기록합니다.

---

## 1주차 1일차 — 기본 이동과 카메라

### 목표

3인칭 캐릭터의 기본 조작을 구현한다.

### 구현 내용

- `PMCharacter` C++ 클래스 구성
- Enhanced Input 연결
- WASD 이동 구현
- 마우스 카메라 회전 구현
- 점프 구현
- Spring Arm과 Follow Camera 구성
- 마우스 감도 변수 추가
- 테스트 맵 `L_TestMovement` 생성

### 사용한 주요 에셋

- `IA_Move`
- `IA_MouseLook`
- `IA_Jump`
- `IMC_Default`
- `BP_PMCharacter`
- `BP_ParryingGameMode`

### 테스트 결과

- WASD 이동 정상
- 카메라 기준 이동 방향 계산 정상
- 마우스 카메라 회전 정상
- 점프 정상
- GameMode를 통한 플레이어 생성 정상

### 배운 점

- Input Action은 행동을 정의하고 Input Mapping Context는 실제 키를 연결한다.
- C++ 클래스는 기능을 구현하고 블루프린트는 입력 에셋과 캐릭터 리소스를 연결한다.
- `UPROPERTY`를 사용하면 C++ 변수를 블루프린트에서 조절할 수 있다.

## 1주차 2일차 — 달리기

### 목표

왼쪽 Shift를 누르는 동안 캐릭터가 달리도록 구현한다.

### 구현 내용

- `IA_Sprint` 생성
- `IMC_Default`에 Left Shift 매핑
- `WalkSpeed`와 `SprintSpeed` 추가
- `StartSprint()` 구현
- `StopSprint()` 구현
- 입력 취소 시 걷기 속도로 복귀하도록 처리

### 설정값

| 항목 | 값 |
|---|---:|
| Walk Speed | 350 |
| Sprint Speed | 600 |
| Camera Arm Length | 400 |
| Mouse Sensitivity | 0.3 |

### 테스트 결과

- Shift를 누르는 동안 달리기 정상
- Shift를 놓으면 걷기 속도로 복귀
- 입력을 반복해도 속도가 누적되지 않음
- 이동, 점프, 카메라와 함께 정상 작동

### 발생한 문제

달리기 입력 추가 이후 WASD가 카메라를 회전시키고 마우스 카메라 입력이 작동하지 않는 문제가 발생했다.

자세한 해결 과정은 다음 문서에 기록했다.

- [입력 매핑 오류 해결](TROUBLESHOOTING.md#입력-매핑-오류)

## 1주차 3일차 — 회피 구르기

### 목표

왼쪽 Ctrl을 누르면 캐릭터가 이동 방향으로 회피하고, 쿨다운을 통해 연속 사용을 제한하도록 구현한다.

### 구현 내용

- `IA_Dodge` 생성
- `IMC_Default`에 Left Ctrl 매핑
- `DodgeStrength`와 `DodgeCooldown` 추가
- `Dodge()`와 `ResetDodge()` 구현
- 이동 입력에 따른 회피 방향 계산
- 정지 상태에서는 캐릭터 정면으로 회피하도록 처리
- 공중 회피 및 연속 사용 제한
- 타이머를 이용한 회피 쿨다운 구현

### 설정값

| 항목 | 값 |
|---|---:|
| Dodge Key | Left Ctrl |
| Dodge Strength | 900 |
| Dodge Cooldown | 0.6초 |

### 테스트 결과

- 이동 중 회피하면 현재 이동 입력 방향으로 회피한다.
- 정지 상태에서 회피하면 캐릭터 정면으로 회피한다.
- 점프 또는 낙하 중에는 회피할 수 없다.
- 회피 직후 연속으로 회피할 수 없다.
- 쿨다운이 끝나면 다시 회피할 수 있다.
- 기존 이동, 카메라, 점프, 달리기가 정상적으로 작동한다.

### 현재 한계 및 향후 개선

- 아직 회피 애니메이션이 없어 캐릭터가 미끄러지는 것처럼 보인다.
- 현재 이동은 `LaunchCharacter()`를 사용한다.
- 이후 회피 애니메이션 몽타주를 연결할 예정이다.
- 애니메이션에 Root Motion을 적용할 경우 기존 이동 방식을 조정할 예정이다.
- 적의 공격 시스템을 구현한 뒤 회피 무적 시간을 추가할 예정이다.
- 스태미나 시스템 구현 후 회피 시 스태미나가 감소하도록 확장할 예정이다.

## 1주차 4일차 — 기본 공격

### 목표

마우스 왼쪽 버튼을 누르면 기본 공격 애니메이션을 재생하고, 공격 중 연속 입력을 제한하도록 구현한다.

### 구현 내용

- `IA_Attack` 생성
- `IMC_Default`에 마우스 왼쪽 버튼 매핑
- `AM_Player_Attack_01` 애니메이션 몽타주 생성
- `AttackAction`과 `AttackMontage` 추가
- `Attack()`과 `ResetAttack()` 구현
- 공격 중 연속 입력 제한
- 공중 공격 제한
- 몽타주 재생 시간에 맞춘 공격 상태 초기화

### 테스트 결과

- 마우스 왼쪽 버튼 입력 시 공격 몽타주가 정상적으로 재생된다.
- 공격 중 마우스를 연속 클릭해도 몽타주가 중복으로 실행되지 않는다.
- 공격 애니메이션이 종료된 후 다시 공격할 수 있다.
- 점프 또는 낙하 중에는 공격할 수 없다.
- 기존 이동, 카메라, 점프, 달리기, 회피 기능이 정상적으로 작동한다.

### 현재 한계 및 향후 개선

- 아직 공격 판정과 피해 적용은 구현하지 않았다.
- 현재 공격 애니메이션은 기능 검증을 위한 임시 애니메이션이다.
- 공격 중 전진 이동과 발동작이 일치하지 않아 미끄러지는 것처럼 보인다.
- 이후 발을 내딛는 공격 애니메이션으로 교체하거나 Root Motion을 조정할 예정이다.
- 애니메이션의 실제 타격 시점에 맞춰 공격 판정을 추가할 예정이다.

## 1주차 5일차 — 체력 및 사망 시스템

### 목표

플레이어와 적이 공통으로 사용할 수 있는 체력 컴포넌트를 구현하고 피해 및 사망 처리를 테스트한다.

### 구현 내용

- `UPMHealthComponent` 액터 컴포넌트 생성
- 최대 체력과 현재 체력 관리
- 언리얼의 `OnTakeAnyDamage` 이벤트 연결
- 피해량에 따른 체력 감소 및 범위 제한
- 체력 변경 및 사망 델리게이트 구현
- 체력 비율과 사망 상태 조회 함수 구현
- `APMCharacter`에 체력 컴포넌트 추가
- 사망 시 플레이어 이동과 입력 비활성화
- 테스트용 `BP_DamageZone` 구현

### 설정값

| 항목 | 값 |
|---|---:|
| Max Health | 100 |
| Damage Zone Damage | 25 |

### 테스트 결과

- 피해 구역 진입 시 체력이 25씩 감소한다.
- 체력이 0 아래로 내려가지 않는다.
- 체력이 0이 되면 사망 이벤트가 한 번 발생한다.
- 사망 후 플레이어 이동과 입력이 비활성화된다.
- 현재 체력이 출력 로그에 정상적으로 표시된다.
- 기존 이동, 카메라, 점프, 달리기, 회피 및 공격 기능이 정상적으로 유지된다.

### 현재 한계 및 향후 개선

- 현재 체력은 출력 로그에서만 확인할 수 있다.
- 이후 플레이어 체력 바 UI를 추가할 예정이다.
- 아직 플레이어 공격으로 다른 액터에게 피해를 적용할 수 없다.
- 공격 판정과 테스트용 적 캐릭터를 구현한 뒤 체력 컴포넌트를 연결할 예정이다.
- 피격 및 사망 애니메이션은 추후 추가할 예정이다.

## 1주차 6일차 — 체력 HUD와 테스트 더미

### 목표

플레이어의 현재 체력을 화면에 표시하고, 체력 및 사망 시스템을 재사용할 수 있는 테스트 더미를 구현한다.

### 구현 내용

- `WBP_HUD` 위젯 블루프린트 생성
- Canvas Panel과 `PlayerHealthBar` 구성
- `GetHealthPercent()`를 Progress Bar의 진행률에 연결
- `BP_PMCharacter`에서 HUD 생성 및 Viewport 추가
- `BP_TestDummy` 액터 생성
- 테스트 더미에 `PMHealthComponent` 추가
- 테스트 더미 사망 시 충돌 비활성화
- 테스트 더미 사망 시 숨김 및 제거 처리
- `L_TestMovement`에 테스트 더미 배치

### 테스트 결과

- 플레이 시작 시 체력 바가 화면에 정상적으로 표시된다.
- 피해 구역에 들어가면 플레이어 체력과 체력 바가 함께 감소한다.
- 체력이 0이 되면 체력 바가 비고 플레이어 조작이 제한된다.
- 테스트 더미에 최대 체력 100이 정상적으로 설정된다.
- 테스트 더미의 `OnDeath` 이벤트가 사망 처리 노드에 연결된다.
- 기존 이동, 카메라, 점프, 달리기, 회피 및 공격 기능이 정상적으로 유지된다.

### 현재 한계 및 향후 개선

- 체력 바는 현재 매 프레임 체력 비율을 조회하는 Property Binding 방식을 사용한다.
- 이후 `OnHealthChanged` 이벤트 기반으로 변경해 불필요한 반복 조회를 줄일 예정이다.
- 아직 플레이어 공격 판정이 없어 테스트 더미를 직접 공격할 수 없다.
- 다음 단계에서 공격 판정과 피해 적용을 연결할 예정이다.
- 테스트 더미는 임시 Static Mesh를 사용하며 실제 적 모델과 애니메이션은 추후 추가할 예정이다.

## 1주차 7일차 — 공격 판정과 통합 테스트

### 목표

공격 애니메이션의 타격 시점에 근접 공격 판정을 실행하고, 테스트 더미에게 피해와 사망 처리를 적용한다.

### 구현 내용

- 공격 설정값 `AttackDamage`, `AttackRange`, `AttackRadius` 추가
- 공격 몽타주에 `AttackHit` Montage Notify 추가
- Montage Notify 이벤트와 C++ 함수 연결
- `PerformAttackTrace()` 근접 공격 판정 구현
- 구체 Sweep를 이용한 전방 범위 검사
- `PMHealthComponent`를 가진 액터만 피해 대상으로 처리
- 한 번의 공격에서 같은 액터의 중복 피해 방지
- `ApplyDamage()`를 이용한 테스트 더미 피해 적용
- 공격 판정 범위 디버그 표시
- 1주차 기능 통합 테스트

### 설정값

| 항목 | 값 |
|---|---:|
| Attack Damage | 20 |
| Attack Range | 150 |
| Attack Radius | 50 |
| Test Dummy Max Health | 100 |

### 테스트 결과

- 공격 애니메이션의 타격 순간에만 공격 Trace가 실행된다.
- 공격 범위 안의 테스트 더미 체력이 한 번에 20씩 감소한다.
- 하나의 공격으로 같은 테스트 더미가 중복 피해를 받지 않는다.
- 다섯 번 공격하면 테스트 더미 체력이 0이 된다.
- 테스트 더미 사망 시 충돌이 꺼지고 화면에서 제거된다.
- 공격 범위 밖의 테스트 더미는 피해를 받지 않는다.
- 이동, 카메라, 점프, 달리기, 회피, HUD 및 플레이어 피해 처리가 정상적으로 유지된다.

### 현재 한계 및 향후 개선

- 현재 기본 공격은 임시 애니메이션 한 종류만 사용한다.
- 공격 판정은 `Visibility` 채널을 사용하는 단순 구체 Sweep 방식이다.
- 이후 무기 소켓과 무기 궤적 기반 판정으로 개선할 예정이다.
- 공격 상태 종료는 몽타주 재생 시간을 이용한 타이머 방식이다.
- 이후 몽타주 종료 이벤트를 이용하도록 개선할 예정이다.
- 플레이어 피격 및 사망 애니메이션과 레벨 재시작은 아직 구현하지 않았다.

### 1주차 회고

- C++에서 게임 규칙과 기능을 구현하고 Blueprint에서 에셋과 설정값을 연결하는 구조를 이해했다.
- Enhanced Input을 이용해 이동, 점프, 달리기, 회피 및 공격 입력을 연결했다.
- Actor Component를 이용해 플레이어와 적이 재사용할 수 있는 체력 시스템을 구현했다.
- Animation Montage와 Notify를 이용해 애니메이션과 공격 판정의 타이밍을 연결했다.
- Git 커밋을 이용해 기능 단위로 변경사항을 기록하고 문제가 발생한 에셋을 복구했다.

## 2주차 1일차 — 기본 적 캐릭터

### 목표

기존 체력 및 공격 판정 시스템을 재사용하여 플레이어가 공격하고 처치할 수 있는 기본 적 캐릭터를 구현한다.

### 구현 내용

- `ACharacter`를 상속하는 `APMEnemyCharacter` C++ 클래스 생성
- 적 캐릭터에 `UPMHealthComponent` 추가
- 적 Capsule 크기와 기본 이동 속도 설정
- 이동 방향을 바라보도록 적 캐릭터 회전 설정
- 체력 컴포넌트의 `OnDeath` 이벤트 연결
- 사망 시 Character Movement 비활성화
- 사망 시 Capsule과 Mesh 충돌 비활성화
- 사망 2초 후 적 캐릭터 자동 제거
- `BP_EnemyCharacter` 블루프린트 생성
- `SKM_Manny_Simple` 스켈레탈 메시 연결
- 적 캐릭터 Animation Blueprint 연결
- 메시의 위치와 회전을 Capsule에 맞게 조정
- Capsule의 `Visibility` 채널을 `Block`으로 설정
- `L_TestMovement`에 적 캐릭터 배치
- 플레이어 공격을 이용한 적 피해 및 사망 테스트

### 설정값

| 항목 | 값 |
|---|---:|
| Max Health | 100 |
| Capsule Radius | 42 |
| Capsule Half Height | 96 |
| Max Walk Speed | 250 |
| Rotation Rate Yaw | 360 |
| Death Life Span | 2초 |
| Visibility Response | Block |

### 테스트 결과

- 적 캐릭터의 메시가 Capsule 안에 정상적으로 배치된다.
- 적 캐릭터의 대기 애니메이션이 정상적으로 재생된다.
- 공격 범위 밖에서는 적이 피해를 받지 않는다.
- 공격 범위 안에서는 플레이어 공격 한 번에 체력이 20씩 감소한다.
- 하나의 공격으로 같은 적에게 피해가 중복 적용되지 않는다.
- 다섯 번 공격하면 적의 체력이 0이 된다.
- 적의 체력이 0이 되면 이동과 충돌이 비활성화된다.
- 사망한 적은 2초 후 자동으로 제거된다.

- 사망 시 피격, 공격 및 회피 쿨다운 타이머 정리

### 설정값

| 항목 | 값 |
|---|---:|

### 상태 처리

```text
OnHealthChanged
→ 현재 체력과 PreviousHealth 비교

```

- 기존 적 추적, 공격, 플레이어 피해 및 HUD 기능이 정상적으로 유지된다.

- 공격 애니메이션을 세 종류로 늘려 1타, 2타, 3타가 서로 다른 동작으로 재생되도록 확장할 예정이다.
- 하나의 공격 몽타주에 `Attack1`, `Attack2`, `Attack3` Section을 구성할 예정이다.
- 공격 중 아무 때나 다음 동작으로 넘어가지 않도록 별도의 콤보 입력 가능 구간을 설정할 예정이다.
- 입력 가능 구간에 공격 키가 눌리면 다음 공격을 예약하고, 현재 공격이 연결 지점에 도달했을 때 다음 Section으로 전환할 예정이다.
- 3타가 종료되거나 일정 시간 동안 추가 입력이 없으면 콤보 단계를 1타로 초기화할 예정이다.
- 피격 또는 사망으로 공격이 취소되면 현재 콤보 단계와 예약된 공격 입력도 함께 초기화할 예정이다.
- 이후 검 공격 애니메이션과 무기 궤적 판정으로 교체하더라도 같은 연속 공격 구조를 재사용할 수 있도록 구현할 예정이다.

## 2주차 6일차 — 플레이어 3단 연속 공격

### 목표

서로 다른 세 종류의 공격 애니메이션을 하나의 몽타주에 구성하고, 정해진 입력 가능 구간에 들어온 공격 입력을 예약하여 다음 공격으로 연결되는 3단 콤보를 구현한다.

### 구현 내용

- `AM_Player_Attack_01`에 `MM_Attack_01`, `MM_Attack_02`, `MM_Attack_03` 배치
- 공격별 `Attack1`, `Attack2`, `Attack3` Montage Section 구성
- 한 번의 입력으로 모든 공격이 자동 재생되지 않도록 Section 기본 연결 제거
- 각 공격의 타격 시점에 `AttackHit` Montage Notify 배치
- 1타와 2타에 `ComboWindowOpen`, `ComboWindowClose` Montage Notify 배치
- 현재 콤보 단계를 관리하는 `CurrentComboIndex` 추가
- 다음 입력 허용 상태를 관리하는 `bCanQueueCombo` 추가
- 다음 공격 예약 상태를 관리하는 `bComboInputQueued` 추가
- 최대 콤보 단계를 나타내는 `MaxComboCount` 추가
- 첫 공격을 시작하는 `StartCombo()` 구현
- 콤보 단계에 해당하는 Section 이름을 반환하는 `GetComboSectionName()` 구현
- 예약 입력에 따라 다음 Section을 연결하는 `TryContinueCombo()` 구현
- 전체 콤보 상태를 초기화하는 `ResetCombo()` 구현
- `Montage_SetNextSection()`을 이용한 다음 공격 연결
- 공격 몽타주 종료 이벤트와 `HandleMontageEnded()` 연결
- 기존 공격 종료용 `AttackTimer`와 `ResetAttack()` 제거
- 정상 종료와 강제 취소에서 `ResetCombo()` 재사용
- 피격 또는 사망 시 공격 몽타주와 예약된 콤보 입력 정리
- 세 공격 모두 기존 `AttackDamage`와 `PerformAttackTrace()` 재사용
- `ABP_Unarmed`에서 `Control Rig`과 `DefaultSlot` 노드 순서 변경
- 공격 몽타주가 Foot IK 이후에 적용되도록 구성
- 콤보 점검을 위한 임시 출력 로그 추가 후 제거

### 설정값

| 항목 | 값 |
|---|---:|
| Max Combo Count | 3 |
| Combo Sections | Attack1, Attack2, Attack3 |
| Attack Animations | MM_Attack_01, MM_Attack_02, MM_Attack_03 |
| Attack Damage | 20 |
| Combo Input Storage | bool |
| Section 연결 방식 | Montage_SetNextSection |
| 공격 종료 처리 | OnMontageEnded |

### 상태 처리

```text
공격 입력
├─ 공격 중이 아님
│  → StartCombo()
│  → CurrentComboIndex = 1
│  → Attack1 재생
│
└─ 공격 중
   ├─ Combo Window 열림
   │  → 다음 공격 입력 예약
   └─ Combo Window 닫힘
      → 입력 무시

ComboWindowClose
├─ 예약 입력 있음
│  → 다음 Section 연결
│  → 콤보 단계 증가
│  → 예약 입력 소비
│
└─ 예약 입력 없음
   → 현재 Section 종료까지 재생
   → 몽타주 종료 이벤트
   → ResetCombo()

피격 또는 사망
→ CancelAttack()
→ 공격 몽타주 중단
→ ResetCombo()
```

### 테스트 결과 

- 공격 키를 한 번 누르면 1타만 재생된다.
- 입력 가능 구간 밖에서 누른 공격 입력은 무시된다.
- 1타의 Combo Window에서 입력하면 2타로 연결된다.
- 2타의 Combo Window에서 입력하면 3타로 연결된다.
- 공격 키를 반복해서 눌러도 공격 단계를 건너뛰지 않는다.
- 각 공격의 AttackHit 시점에 피해가 한 번씩 적용된다.
- 추가 입력이 없으면 현재 공격까지만 재생한 뒤 콤보가 초기화된다.
- 3타 종료 후 다음 공격은 다시 1타부터 시작한다.
- 피격 또는 사망 시 진행 중인 콤보와 예약 입력이 초기화된다.
- 3타 발차기 애니메이션에서 다리가 꼬이던 문제가 해결되었다.
- 기존 피격, 경직, 적 공격, 피해 및 HUD 기능이 정상적으로 유지된다.

### 현재 한계 및 향후 개선

- 세 공격은 현재 동일한 공격 피해량과 구체 Sweep 판정을 사용한다.
- 공격 중 전진 이동과 방향 보정이 없어 움직이는 적을 맞히기 어렵다.
- 이후 공격 시작 방향을 이동 입력 또는 가까운 적 방향으로 보정할 예정이다.
- 공격마다 짧은 전진 이동 또는 Root Motion을 적용할 예정이다.
- 현재 콤보 구성은 세 단계와 고정된 Section 이름을 사용한다.
- 이후 무기별 콤보 데이터와 공격 단계별 피해량으로 확장할 예정이다.
- 현재 맨손 공격을 사용하며 이후 검 공격과 무기 궤적 기반 판정으로 교체할 예정이다.
